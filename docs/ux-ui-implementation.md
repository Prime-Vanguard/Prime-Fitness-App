## Persistence changes

Set upserts now update an existing row instead of ignoring duplicate IDs. They request the accepted ID and retain local pending state if no row is returned. A local edit revision plus payload comparison prevents an older in-flight acknowledgement from clearing a newer edit or Undo. Local revision bookkeeping is stripped before sending data to Supabase.

Edits to a set changed by another tab are rejected with a reopen instruction. This does not introduce a server-side revision protocol for simultaneous edits on separate devices; that remains a validation/design limitation, not a claimed conflict-resolution feature.
